# 텍스트 기반 로그라이크 RPG — 개발 계획

> 출처: FigJam 보드 「텍스트 기반 로그라이크 RPG」 (2026-09-28 기준 내용 정리)
> 대상: Godot 4.7 / GDScript, 현재 레포(`word_game`)

---

## 1. 게임 한 줄 요약

전투가 **문장**으로 표현되는 텍스트 로그라이크. 적의 행동은 `주어 + (관형어) + 부사어 + 서술어` 어절로 구성된 문장이고,
**어절 하나가 끝날 때마다 턴이 진행**된다. 유저는 적의 문장이 한 어절씩 흘러가는 동안(= 다음 턴까지의 대기시간)
자신의 행동(타격/수비…)을 입력해서 대응한다.

```
고블린이  [화염의]  [단검으로]  [빠르게]  찌른다.
 주어      관형어     부사어(수단) 부사어(방식) 서술어
                           ↑ 유저: 방패로  막는다.
→ "고블린에게 총 1만큼의 피해를 받았다.(13 데미지 감소)"
```

## 2. 보드에서 읽어낸 설계 정리

### 2.1 코어 게임 루프
```
게임 시작 → 난이도 선택 → 직업 선택
  → [탐험] → 상황 텍스트 → 선택지 선택
        ├ 일반 선택지 → 보상이 있는가? → 보상 획득
        ├ 이벤트 → 이벤트 종류 ─ 상황 이벤트 → (일반 선택지 흐름)
        │                    └ 전투 이벤트 → 전투 phase
        └ 전투 → 전투 phase
  → 보상 획득/성장 → [탐험]으로 복귀 … → 게임 종료
```
보상 종류: 최대 체력 증가, 체력 회복, 돈, 무기, 스킬, 선택지 해금, 스탯 증가.

### 2.2 전투 흐름 (battle flowchart)
```
전투 시작 → 적에 대한 묘사 → 다음 문장 불러오기(★패턴 생성)
  → [sentence phase]
      문장 시작 → 어절 진행(턴 대기) ← 플레이어 Input
        → [turn phase]
            턴 시작 → 어절 효과 적용 → turn 기반 effect 적용 → 결과 계산 → 시스템 text 업데이트
            → 유저 그로기? ─YES→ 유저의 이후 어절 취소 → 유저 경직 effect 부여 ─┐
            → 적 그로기?  ─YES→ 다음 문장에 그로기 문장 추가 → 적의 이후 어절 취소(문장 종료 취급)
            → 전투 종료? ─YES→ 전투 종료
            → 턴 종료
        → 문장 종료? ─NO→ 어절 진행
                     ─YES→ 문장 종료 → 문장 기반 effect 적용 → 시스템 text 업데이트
  → 전투 종료? ─NO→ 다음 문장 불러오기 / ─YES→ 전투 종료
```
- 문장 패턴은 **‘다음 문장 불러오기’ 시점에 확정**된다 (턴 phase 중 변경 없음).
- 보드의 턴 예시: 적 문장이 `sentence start → 1 turn → 2 turn → … → sentence end` 로 한 어절씩 공개되고,
  유저는 중간 턴에 `수비하기`를 입력해 `방패로 막는다.`가 적 문장과 병렬로 진행된다.

### 2.3 패턴(문장) 생성 (Pattern Generate)
```
패턴 생성 시작 → 패턴(기본 문장) 선택 → 무기 선택
  → 무기 관형어 추가 여부 결정 ⟲ (관형어 추가? YES → 무기 관형어 선택)
  → 부사어 추가 여부 결정     ⟲ (부사어 추가? YES → 부사어 선택)
  → 이어진 문장 여부 결정 → 이어진 문장? ─YES→ 서술어 선택 → 무기 선택 …(반복)
                                        ─NO→ 패턴 생성 종료
```

### 2.4 문법 규칙 (생성기가 지켜야 할 제약)
**기본 문장**
- 구조는 주어 + 서술어(SV).
- 서술어 앞에 **수단의 부사어(무기) 정확히 1개**.
- 서술어 앞에 **방식의 부사어(어떻게) 1개 이상**.
- 행위자에게 무기 강화형 Effect가 있으면 수단 부사어 앞에 **관형어(어떤)** 가 붙는다.
  관형어가 2개 이상이면 앞 관형어의 조사가 `~와/과`로 바뀐다. (예: 화염과 맹독의 단검으로)

**이어진 문장**
- 특정 조건 또는 확률로 발생.
- 기본 서술어 어미가 연결어미 `~고,`로 바뀌고, 뒤에 **연결 부사어(또, 다시) 1개**.
- 이어진 서술어 앞에 방식 부사어 1개 이상, 수단 부사어는 0~1개.
  기본 문장과 같은 무기면 제거. 무기가 없으면 기본 문장 무기의 효과를 받는다.

**부사어**
- 같은 문장/서술어에 충돌 부사어가 있으면 생성 불가 (`conflictingAdverb`).
- 방식 부사어가 연속되면 앞 부사어 어미가 `~고`로 바뀔 수 있다 (빠르고 강하게).
- 효과 범위: 문장 내 모든 서술어 / 수식하는 서술어만 (`modifyRange`).
- 부사어마다 등장확률 계수(가중치)를 가진다.

**한국어 처리**: 받침 여부(`haveBatchim`)로 조사 선택 — 이/가, 은/는, 으로/로, 와/과. 어미 변환 — `찌른다.` ↔ `찌르고,`, `빠르게` ↔ `빠르고`.

### 2.5 스탯 / Effect / 강인도·그로기
| 구분 | 항목 |
|---|---|
| 재화 | 돈 (아이템 구매, 선택지, 이벤트, 스킬 부가효과) |
| 기본 스탯 | HP(현재/최대 구분, 0이면 사망 — 부활 effect 없으면 회복 불가), STR, DEX, INT, CHA (각 기반 기술 + 선택지 조건) |
| 전투 스탯 | 회피율, 치명타확률, 치명타피해(배율), 강인도, 흡혈 |

| Effect | 발동 시점 | 동작 |
|---|---|---|
| 출혈 | 서술어 효과 발동 시 | 수치만큼 피해(감소 무시) |
| 중독 | 3턴마다 | 수치만큼 피해, 3턴마다 수치 −1 |
| 화상 | 문장마다 | 수치만큼 피해, 문장마다 수치 절반(최소 1) |
| 경직 | 턴마다 | 해당 턴 행동 불가, 턴당 −1 |
| 마력 탈진 | 지능 기술 사용 시 부여 | 이번 전투 동안 INT −수치 |

**강인도/그로기** (수동적인 게임에서 유저가 주도권을 잡게 하는 장치)
- 강인도 바는 HP 바 아래, 유저·적 모두 표시.
- 상대 공격의 **직접 피해**로만 감소 (effect 피해 제외). 감소량 = `deal / maxHp * K` (**K 미정**).
- 적 그로기: 진행 중 문장 취소 → 다음 문장으로 `"고블린은 그로기 상태에 빠졌다!"`(4어절 = 4턴 프리딜) 삽입.
- 유저 그로기: 진행 중 문장 취소 + 경직 3 부여. 취소된 행동의 쿨타임은 돌려주지 않음.

### 2.6 프로토타입 필수 스펙
- **플레이어**: HP 100, STR 12, DEX 10
  - 타격: STR 100% 피해, 선딜 1턴, 쿨 1턴, `주먹으로 때렸다.`
  - 수비: DEX 100% 만큼 피해 차단, 선딜 1턴, 쿨 2턴, `방패로 막았다.`
- **고블린**: HP 100, STR 8, DEX 6
  - 기본: `고블린은 찔렀다.`
  - 패턴1: `고블린은 [단검으로] [빠르게] 찔렀다.`
  - 패턴2: `고블린은 [하늘로] [뛰어올라] [단검으로] [강하게] 찔렀다.`
  - 패턴3: `고블린은 찌르고 [또] 찔렀다.`

## 4. 아키텍처 설계

원칙: **전투 로직은 UI와 분리된 순수 GDScript(RefCounted)** 로 만들고, 씬은 시그널로 결과만 받아 그린다.
→ 에디터 없이 콘솔 로그로 전투를 돌려볼 수 있고, 밸런스 테스트도 자동화 가능.

```
scripts/
├── DB/                       (기존) 시트 → 리소스 생성
├── custom_resources/         (기존 + 추가) *DataResource
├── enums/                    (기존) 값 채우기
├── core/
│   ├── data_registry.gd      [Autoload] id → Resource 조회 (resources/data/** 스캔)
│   ├── rng.gd                시드 기반 RNG + 가중치 뽑기 (로그라이크 재현성)
│   └── game_state.gd         [Autoload] 런 상태: 플레이어, 돈, 층, 해금 등
├── text/
│   ├── josa.gd               조사/어미 처리 (받침 판정: 유니코드 (code-0xAC00)%28)
│   └── sentence_renderer.gd  Sentence → 표시 문자열 / BBCode
├── battle/
│   ├── combatant.gd          스탯, HP, 강인도, effect 목록, 쿨타임
│   ├── eojeol.gd             어절: role(주어/관형어/부사어/서술어/시스템), text, 원본 data, 소유 서술어 index
│   ├── sentence.gd           어절 배열 + 커서, cancel(), is_finished()
│   ├── pattern_generator.gd  2.3/2.4 규칙대로 적 문장 생성
│   ├── action_builder.gd     플레이어 행동 → Sentence (타격/수비)
│   ├── effect_system.gd      TriggerTiming별 effect 발동/감소
│   ├── damage_calc.gd        피해·방어·치명·회피·흡혈·강인도 감소
│   └── battle_manager.gd     2.2 플로우차트 상태 머신, signal 발행
└── ui/
    ├── battle_view.gd        적 문장 어절 카드, 유저 문장 줄, HP/강인도 바, 행동 버튼, 로그
    └── explore_view.gd       상황 텍스트 + 선택지 버튼
scenes/
├── main.tscn                 GameFlow 전환 (타이틀 → 탐험 → 전투 …)
├── battle.tscn
└── explore.tscn
```

### 4.1 BattleManager 상태 머신
```gdscript
enum Phase { BATTLE_START, LOAD_SENTENCE, SENTENCE_START, WAIT_TURN,
             TURN_RESOLVE, SENTENCE_END, BATTLE_END }

signal sentence_loaded(enemy_sentence)
signal eojeol_revealed(side, index)
signal log_added(text)
signal turn_ended(turn_no)
signal battle_finished(result)

func submit_player_action(action_id)   # WAIT_TURN 동안만 수락, 쿨타임/경직 검사
func advance_turn()                    # 타이머 만료 or 디버그 스텝 버튼
```
- `TURN_RESOLVE` 내부 순서는 플로우차트 그대로 한 함수에 고정:
  어절 효과 → turn effect → 결과 계산 → 로그 → 유저 그로기 → 적 그로기 → 전투 종료 판정.
- 턴 진행 방식은 설정으로 분리: **실시간 타이머**(어절당 N초) / **스텝 모드**(버튼). 초기 개발은 스텝 모드.

### 4.2 어절과 효과의 연결
- 각 어절은 `apply(ctx)`를 가진다. 부사어 효과는 `modifyRange`에 따라 소속 서술어 또는 문장 전체 서술어에 누적되고,
  **서술어 어절이 끝나는 턴에 실제 피해가 발생**한다 (주어/부사어 어절 턴은 "준비" 시간).
- 유저 수비(`방패로 막는다`)는 서술어 턴에 "방어 버프(DEX×1.0)"를 켜고, 그 턴과 겹치는 적 서술어 피해를 감산.
- 로그의 `{1}` 자리표시자는 문장 종료 시 누적 피해로 채운다 (`"고블린이 총 14만큼의 피해를 줬다."`).

### 4.3 데이터(시트) 확장 제안
| 시트 | 추가/변경 컬럼 |
|---|---|
| AdverbData | `adverbType` = `MEANS`(수단/무기), `MANNER`(방식), `CONNECT`(연결); `text`, `connectiveText`(빠르고) |
| ModifierData (신규) | 관형어: `modifierID`, `text`(화염의), `requiredEffectID`, `appliedEffectID` |
| VerbData | `text`(찌른다.), `connectiveText`(찌르고,), `damageType`(공격/방어) |
| PlayerActionData (신규) | `actionID`, `verbID`, `meansAdverbID`, `preDelayTurn`, `coolDownTurn`, `statType`, `coefficient` |
| EffectData | `triggerTiming` = `ON_VERB`/`PER_TURN`/`PER_SENTENCE`/`ON_INT_SKILL`, `decayType` = `NONE`/`MINUS_ONE`/`HALF_MIN1`/`MINUS_ONE_PER_INTERVAL` |
| enums | `RangeType` = `ALL_VERBS`/`TARGET_VERB`, `StatType` = `STR`/`DEX`/`INT`/`CHA` |
| EventData / ChoiceData (M6) | 상황 텍스트, 선택지, 조건 스탯, 결과(보상/전투/이벤트) |

| **M6** | 코어 루프 | 난이도·직업 선택 → 탐험 → 선택지(일반/이벤트/전투) → 보상/성장 → 반복 → 사망 시 게임 종료 |
| **M7** | 콘텐츠·밸런스 | 적 3~5종, 무기/스킬, 보상 테이블, 자동 전투 시뮬레이션으로 밸런스 확인 |

**프로토타입 = M0~M3.** 여기서 "어절 = 턴" 전투가 재미있는지 먼저 검증하고, 재미가 확인되면 M4 이후로 진행.

## 6. 결정이 필요한 미정 사항

1. **강인도 감소 계수 K** — 보드에 "고민중". 초기값 제안: `deal / maxHp * maxPoise * 2` (HP 50% 피해 = 강인도 전부).
2. **턴 진행 방식** — 어절당 실시간 타이머인가, 유저 입력 대기인가? (보드 메모: "유저가 동작을 입력할 수 있는 시간" → 타이머 쪽)
3. **피해 발생 시점** — 플로우차트는 매 턴 `결과 계산`, 예시 로그는 문장 종료 시 합산. 제안: 서술어 턴에 계산, 로그 합산은 문장 종료 시.
4. **선딜(1턴)의 의미** — 입력 후 1턴 뒤 발동? 유저 문장의 첫 어절(`방패로`)이 선딜 턴이라고 보면 자연스러움.
5. **유저 행동도 부사어/관형어 생성 규칙을 따르는가** — 유저 무기·스킬이 문장을 확장하는지.
6. **패턴 시각화 규칙** — 보드 텍스트가 "패턴 시각화 관련 턴 종료시"에서 끊겨 있음. 적 문장을 미리 보여주는 범위(전체 공개 vs 한 어절씩)를 정해야 함.
7. **주어 조사** — 보드에 `고블린이`와 `고블린은`이 혼재. 하나로 통일 필요.
